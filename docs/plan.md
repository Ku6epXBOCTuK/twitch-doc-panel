# План рефакторинга: виджет + билдер (монорепо), контент отдельным репо

Статус: план согласован, реализация по шагам (каждый шаг — отдельное
обсуждение/коммит). Выполнено: удаление whitelist'а хостов из виджета (Сущность
1: content.js, viewer, DocRenderer, config-вью).

## Решение по архитектуре

- **Виджет и билдер остаются в этом репо (монорепо).** Билдер и рендерер — один
  контракт: валидатор пропускает ровно тот поднабор markdown, который рисует
  панель (общий `src/shared/md.js`). В одном репо изменения идут синхронно,
  версии не разъезжаются.
- **Раздача билдера для чужих репо** — через композитный GitHub Action
  (`builder/action.yml`) + CLI; позднее при желании можно опубликовать в npm.
- **Контент — отдельный репозиторий** (публикуется в сети как угодно), чтобы им
  могли пользоваться другие люди. В этом репо живёт только тестовый контент —
  фикстуры в папке `fixtures/` для dev-режима и скриншотов. Внутренние
  планы/ресерч — не контент, они сюда не попадают.

## Хостинг контента и CSP (ключевое ограничение платформы)

Расширение Twitch крутится в iframe с CSP, **зашитым на версию при релизе**
(консоль: `connect-src` + `img-src`). Менять его — только новая версия и ревью.
Отсюда правила:

- В **коде виджета** нет whitelist'а: `isContentUrl()` пропускает любой http(s)
  и относительные пути, рендерер чистит контент сам. Реальный фильтр — CSP в
  консоли, общий для всех стримеров.
- **Свой хостинг / кастомные домены для опубликованного расширения невозможны**
  (домен не совпадает с CSP версии); это работает только для Local Test на своём
  канале (личная консоль) либо позже через прокси (см. «Переход», ниже).
- **MVP-доставка (бесплатно, стримеру не нужен dev-аккаунт):** файлы контента
  лежат в корне любого публичного GitHub-репо, каждый стример выбирает режим:
  - **GitHub Pages** — `https://<user>.github.io/<repo>/index.json`;
  - **jsDelivr** —
    `https://cdn.jsdelivr.net/gh/<user>/<repo>@<branch>/index.json` (включение
    Pages не требуется). CSP опубликованной версии (MVP):
    `https://cdn.jsdelivr.net` и `https://*.github.io` (в `connect-src` и
    `img-src`). Отдельный риск: wildcard `*.github.io` должен пройти ревью —
    проверяется в консоли на первом релизе; fallback — jsDelivr (точный хост),
    Pages тогда откладывается.
- **raw.githubusercontent.com в опубликованный CSP не включается** — риск
  rate-лимитов/TOS при трафике; допускается только на этапе Local Test (дев).
- jsDelivr кэширует ветку ~12 ч; мгновенные обновления — пин по SHA
  (конфиг-панель) или правки через Pages. Для MVP-панели это приемлемо.

### Переход при росте популярности (не MVP)

- **EBS-прокси** (свой бэкенд тянет любой URL по конфигу) — один точный домен в
  CSP, любой хостинг стримера.
- **Cloudflare Pages/Worker-прокси** на своём домене — тот же эффект без VM.
  Реализуется позже, кодам виджета почти не трогает (меняется только источник
  URL).

## Сущность 1 — Виджет (панель)

Код не привязан к доменам: грузит index.json с любого http(s) (GitHub Pages,
jsDelivr при пине-доменах из CSP) или по относительному адресу (same-origin
хостинг). В консоли Twitch на версию декларируются домены CSP (см. выше).
`index.json` — в корне раздачи Pages-сайта/репо.

- `src/shared/content.js` _(сделано)_
  - `ALLOWED_CONTENT_HOSTS` / `isAllowedUrl` удалены;
  - `isContentUrl()` — проверка схемы: абсолютные — только http/https,
    относительные пути разрешены (резолвятся от origin виджета);
  - `DEFAULT_INDEX_URL = ''` — дефолта нет, ссылку задаёт владелец канала в
    панели управления (или константа подставляется вручную).
- `src/viewer/App.svelte` _(сделано)_ — статус `bad-host` заменён на `bad-url`
  (невалидная схема из конфига), проверка по whitelist убрана; относительные
  пути из `index.json` (`url`, `banner`) резолвятся от адреса индекса; картинки
  `header-banners/…` и `images/…` из .md — от адреса .md.
- `src/shared/DocRenderer.svelte` _(сделано)_ — `safeImg`: любой `https:`,
  `http:` только для `localhost`/`127.0.0.1`; `safeLink`: любые http(s).
- `src/config/App.svelte` _(сделано)_ — подсказка про URL вместо «белого списка
  хостов».
- `scripts/screenshot.js` — дефолтная папка контента `fixtures`; копирование
  используемых картинок в стейджинг.

## Сущность 2 — Билдер/валидатор (`builder/build.js`, переписать)

Вход: корень репо с доками. Что делает (режим по умолчанию — правки; `--check` —
только отчёт, exit 1 при замечаниях):

1. **Записи в index.json для всех .md** — сканирование корня, `gray-matter`.
   Если нет `title` — подставляется из имени файла + warning.
2. **Front-matter заголовка** — автоматически ставится
   `banner: banners/<id>.<ext>` при наличии файла в `banners/` с тем же именем
   (приоритет расширений: webp → png → jpg → jpeg → gif → svg). Существующий
   валидный banner сохраняется, битый — чинится/убирается с warning.
3. **Чистка контента** — через `marked.lexer` оставляем только то, что умеет
   рисовать панель (heading, paragraph, списки + GFM-чекбоксы, blockquote, hr,
   em/strong/del/codespan, ссылки, картинки, br). Raw HTML, script-теги,
   код-блоки, таблицы удаляются, пересборка из `raw`-фрагментов токенов
   (нормализованный идемпотентный результат). Удалённые конструкции — в отчёт.
4. **Предупреждения о неиспользуемых файлах** — файлы в `banners/` и `images/`,
   на которые не ссылается ни одна запись (`banner` или относительный путь в
   контенте), и лишние файлы в корне.
5. **Битые ссылки** — относительный путь в .md на отсутствующий файл → warning.

Выход: `index.json` в корне папки — `[{id, title, order, hidden, banner, url}]`
(та же схема, что понимает виджет).

## GitHub Actions

- `builder/package.json` (+ lock): gray-matter + marked — самодостаточная
  зависимость экшена.
- `builder/action.yml` — композитный экшен: setup-node → npm ci →
  `node build.js <dir>`.
- `builder/workflow-example.yml` — шаблон для репо с доками: checkout →
  `uses: <owner>/twitch-doc-panel/builder@<ref>` → авто-коммит изменённых .md и
  index.json.
